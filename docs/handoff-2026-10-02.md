## 3. 지금 구조 (바뀐 것 위주)

**동작 관리(`/animate`)**
- 상단 캐릭터 줄(좌우 스크롤)에서 한 명을 고르면 그 캐릭터의 사진·동작·결과만 보임.
- "이 캐릭터의 동작": 타일의 그림을 누르면 재생. `대기 동작으로` / `대기 해제` / `삭제`. 배경이 남은 영상에는 `배경 제거`(무료)와 `AI로 배경 제거`.
- "4. 작업 순서": ① 사진 투명배경화 ② AI 동작 생성 ③ 결과 영상 투명배경화. ①③은 체크박스 + `무료 | AI` 버튼. "동작 만들기" 버튼에 총액 표시.

**대기(idle) 규칙** (`lib/idle.js`)
1. 사용자가 고른 동작(`library.idleChoice[photoId]`)
2. 예전 방식으로 올린 대기 파일(`library.idles`)
3. 그 사진의 가장 최근 "대기 동작"(대기 예시로 만든 결과이거나 이름에 `대기`/`idle` 포함)
4. 사진 그대로
- idle로 쓰이는 동작은 방송 화면의 동작 버튼에서 빠짐.

**배경 제거**
- 무료(서버 안, 비용 0): 사진은 단색 배경만(`lib/animate/cutout.js`, 가장자리 색 섞임 제거 포함), 영상은 초록·파랑·분홍 키 또는 가장자리와 이어진 단색.
- AI(WaveSpeed, 유료): `lib/animate/background-ai.js`. 사진은 투명 PNG로 옴. **영상은 투명으로 안 옴** — 단색 키 색 이미지를 `background_image`로 같이 보내고, 돌아온 영상에서 그 색을 우리 서버가 지움.
- 버튼으로 사진 배경을 지우면 **원본은 그대로 두고 새 사진이 추가됨**. AI 결과는 `photos/<id>.aicut.png`에 보관되어 같은 사진은 다시 과금되지 않음.

**자동 반응** (`lib/director/`, 방송 화면 `/broadcast`)
- 브라우저 마이크 → Soniox 실시간 STT(임시 키) → `POST /api/director/speech` → 서버가 1초마다(새 대사가 있을 때만) AI에 판단 요청 → 대기열 → 순차 재생.
- AI: OpenAI Decisions API(`POST /v1/decisions`, 요청 형식은 **추정**). 거절되면 같은 키로 Chat Completions(`gpt-6-luna`)로 자동 전환.
- 과금: 판단+음성 인식 합쳐 1분에 8크레딧, 1분 단위 선차감, 켠 계정에서 차감(#70).

**예시 동작 영상**
- 로그인 켜진 환경에서는 `data/animate/drivings/examples/` 한 곳을 모든 계정이 공유(버킷에도 보관). 서버 시작 시 없는 것을 자동으로 받음. 계정이 지우면 그 계정에서만 숨김.

**배포가 겹칠 때의 생성 작업** (`lib/animate/pipeline.js`, #69)
- DB를 쓰는 환경에서는 진행 중인 작업마다 `job.lease = { owner, until }`(서버 인스턴스 id, 60초)를 남기고 20초마다 갱신.
- 새 서버는 다른 서버가 잡고 있는 작업을 돌리지 않고 10초마다 지켜봄(진행 상황은 화면에 전달). lease가 풀리거나 만료되면 이어받음. 다른 서버가 새로 만든 작업도 같은 방식으로 발견.
- SIGTERM: 새 작업 시작 중지 → 제출 중인 작업은 최대 20초 기다려 task를 저장(이중 제출 방지) → 나머지 중단 → 버킷 업로드 → lease 해제. 이어받는 서버는 필요한 입력 파일을 버킷에서 받음(`mirror.restore`).
- 겹치는 동안 다른 서버 작업의 환불·차감은 그 서버가 처리(이 서버는 화면 갱신만).

**실시간 연결**
- `public/motions.js`의 `liveEvents`: 오류 응답으로 닫힌 EventSource를 3초마다 다시 엶. 오버레이(OBS)도 같은 처리. 동작 관리는 진행 중 작업을 5초마다 추가로 조회.

## 5. 알려진 이슈와 미검증 항목

1. **자동 반응은 실제 키로 한 번도 돌려보지 않음.** Decisions API 요청 형식이 추정이라, 켜 보고 카드의 "방금 판단" 줄에서 `Decisions API`인지 `일반 호출 (Decisions API 사용 불가)`인지, `AI 오류`가 뜨는지 확인해야 함. Railway에 `OPENAI_API_KEY`, `SONIOX_API_KEY`는 등록돼 있음.
2. **AI 영상 배경 제거 수정(#63)을 배포된 서버에서 끝까지 눌러 확인하지 않음.** 실제 응답 두 개를 새 코드에 통과시켜 투명 영상이 나오는 것까지만 확인.
3. **자동 반응 과금 방식은 제가 정한 것**: 5분 단위 선차감(중간에 꺼도 그 블록은 환불 없음), 음성 인식 요금은 마이크 사용 여부와 무관하게 Soniox 키가 있으면 부과. 사용자 확인 필요.
4. **`railway.json`을 Railway가 읽지 않음**(이유 미확인). 헬스체크는 API로 서비스 설정에 직접 넣었음. 파일은 저장소에 남아 있음.
5. **`railway redeploy`는 예전 설정으로 다시 띄움.** 설정 변경은 새 배포(푸시 또는 `serviceInstanceDeployV2`)부터 적용됨.
6. **배포가 겹치는 몇 초**: 생성 작업은 #69로 이어받음. 다만 원장(크레딧)은 서버마다 시작 때 읽은 메모리 사본이라, 겹치는 동안 이전 서버에서 생긴 차감을 새 서버가 환불해야 하는 경우(이어받은 작업이 실패)에는 환불이 안 될 수 있음. 겹치는 동안 새 서버 화면에서 이전 서버 작업을 취소하면 이전 서버가 덮어쓸 수 있음.
7. **캐릭터 2의 기존 동작(원영턴 등)**은 흰 배경 잔상이 남아 있음. 가장자리 개선은 새로 만드는 것부터 적용되므로 다시 만들어야 깨끗해짐(생성 비용 발생).

## 6. 주의사항

- **새 AI·외부 유료 호출은 먼저 제안하고 승인받은 뒤 붙일 것.** 사용자 키로 진단용 호출을 할 때도 먼저 물어볼 것. (이 스레드에서 영상 배경 제거 진단으로 2회, 약 $0.06을 묻지 않고 썼음.)
- **로컬에서 `node server.js`를 실제 `.env`로 돌리지 말 것.** `.env`에 운영 DB·R2 값이 들어 있어서 실제 버킷과 동기화됨. 화면 확인은 임시 폴더로 `createAppServer`를 띄워서 할 것(스크래치패드에 `dev-server.js` 패턴 사용).
- 운영 조회는 읽기 전용으로: 변수 이름만 출력, 로그는 URL 가림. Railway 변수 변경·삭제는 승인 필요.
- 커밋·푸시·병합은 요청이 없어도 바로 진행하는 것이 이 사용자의 기본 방침(브랜치 → PR → 병합). 병합하면 Railway가 자동 배포함.
- 답변은 간단명료하게, 맨 끝에 100자 이내 요약과 사용자가 할 일을 적을 것.
- Railway 볼륨 `virtually-volume`(약 793MB)은 어느 서비스에도 붙어 있지 않은 고아 상태. 삭제는 승인 필요.
